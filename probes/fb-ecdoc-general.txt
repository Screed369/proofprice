			<h3 id="whatisitabout"><a class="link" href="#whatisitabout">What is it about?</a></h3>
			<div class="paragraph" style="line-height:1.5em">
				An API, short for Application Programming Interface, is a set of services that can be called from a computer program (“Machine to Machine” interface).
				It's a computer interface, as opposed to a (human) graphical user interface.
				Technically the Agri-food Data API is a <strong>Web API,</strong> consisting of a set of addresses (URLs) that may be used to retrieve information from
				the portal's database. The information is substantially the same as what you can see in the "Data Explorer" tab of the corresponding portal app,
				but the format is suitable for consumption by computers rather than human beings – even though humans can still read it! It is formatted in a structure
				known as <a href="https://www.w3.org/standards/webarch/metaformats.html" style="color:#004494; text-decoration:none" target="_blank" ><strong>JSON</strong></a>.
			</div><br>
			<div class="paragraph" style="line-height:1.5em">
				Here is an example of a query URL to retrieve some Slovenian pigmeat prices prices from 2020:
			</div>

			<h3>Using your favourite spreadsheet application</h3>
			<div class="paragraph" style="line-height:1.5em">
				A relatively simple way of putting the API to work is by launching the query from <strong>inside a spreadsheet application</strong>. Consult the documentation
				of your favourite spreadsheet tool and look for something like “getting data from the Web”. Where it says "address" or "URL", paste the above URL.
				In some spreadsheet applications this may require writing a macro.
			</div><br>

			<h3>Rate limiting policy: protection against API abuse</h3>
			<div class="paragraph" style="line-height:1.5em">
				Our API is protected against abusive behaviour. We have in place a rate limiting policy
				to protect the application and the ability for users to fetch data in an orderly and sensible manner.<br>
			</div><br>

			<h3>CORS policy: protection against cross-scripting attacks</h3>
			<div class="paragraph" style="line-height:1.5em">
				Https responses from API endpoints do not enable <a href="https://en.wikipedia.org/wiki/Cross-origin_resource_sharing" style="color:#004494; text-decoration:none" target="_blank"><strong>CORS</strong></a> scripting.<br>
			</div><br>
			<div class="paragraph" style="line-height:1.5em">
				If you try to make our data available to users within your organisation by developing an internal web application of your own, please be aware that modern browsers will block third-party responses (where the Agri-food data portal API is the third party in this case) by default.
			</div><br>
			<div class="paragraph" style="line-height:1.5em">
				As a web developer, you may circumvent this limitation by offering our data through a proxy service under the same hostname and port number as your web application. From the perspective of the browser, the web application and the data will then appear to come from a single web server.
			</div><br>
			<div class="paragraph" style="line-height:1.5em">
				As an end user, you can configure your browser to disable protection against cross-scripting, but obviously this comes with the risk of exposure to such attacks.
			</div><br>

			<h3>Query monitoring</h3>
