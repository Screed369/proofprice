            <div id='overview'>
                
            <h2 class="govuk-heading-l">Overview</h2>
        <div class="app-rte-content">
            <p>The UK Trade Info API is based on REST principles with endpoints that return data in JavaScript Object Notification (JSON) format and it uses standard HTTP error response codes. </p>
<p>Use the API to get access to data about:</p>
<ul>
<li>Overseas Trade Statistics (OTS)</li>
<li>Regional Trade Statistics (RTS)</li>
<li>imports, exports, traders, commodities, and various other feeds</li>
</ul>
<p>All endpoints are:</p>
<ul>
<li><a rel="noopener" href="https://developer.service.hmrc.gov.uk/api-documentation/docs/authorisation/open-access-endpoints" target="_blank" title="Open access endpoints">open access</a></li>
<li>can be queried</li>
</ul>
<p>They do not need an Authorisation HTTP header.</p>
<p><a href="#contents" data-anchor="#contents">Back to contents</a></p>
        </div>

            <div id='making-api-requests'>
                
            <h2 class="govuk-heading-l">Making API requests</h2>
        <div class="app-rte-content">
            <div class="app-rte-content">
<p>To query the HMRC UK Trade Info API, you will need:</p>
<ul>
<li>
<p>a way to make HTTP requests, such as curl, Postman or your programming language's library of choice</p>
</li>
<li>
<p>a specific query</p>
</li>
</ul>
<p>With the query to find all traders that exported ‘Live horses (excl. pure-bred for breeding)’ from the ‘CB8’ post code in 2019, you can follow these steps to find your answer.</p>
<ol>
<li>
<p>Create a new GET request.</p>
</li>
<li>
<p>Point it towards the API’s base endpoint: <code>https://api.uktradeinfo.com</code></p>
</li>
<li>
<p>Append this <code>/Commodity</code> to the query: we are searching for ‘Live horses (excl. pure-bred for breeding)’, which is a Harmonised System (HS) level 6 commodity.</p>
</li>
<li>
<p>Add two query parameters:</p>
<ul>
<li>
<p><code>$filter=Hs6Code eq '010129'</code><br />010129 is the HS6 code for ‘Live horses (excl. pure-bred for breeding)‘. Alternatively, use <code>Hs6Description eq 'Live horses (excl. pure-bred for breeding)'</code></p>
</li>
<li>
<p><code>$expand=Exports($filter=MonthId
 ge 201901 and MonthId le 201912 and startswith(Trader/PostCode, 'CB8'); $expand=Trader)</code></p>
</li>
</ul>
</li>
<li>The full query URL is (follow the link to open the result in a new browser tab): <a rel="noopener" href="https://api.uktradeinfo.com/Commodity?$filter=Hs6Code eq '010129'&amp;$expand=Exports($filter=MonthId ge 201901 and MonthId le 201912 and startswith(Trader/PostCode, 'CB8'); $expand=Trader)" target="_blank" title="Getting started example: find all traders that exported 'Live horses (excl. pure-bred for breeding)' from the 'CB8' post code in 2019." data-anchor="?$filter=Hs6Code eq '010129'&amp;$expand=Exports($filter=MonthId ge 201901 and MonthId le 201912 and startswith(Trader/PostCode, 'CB8'); $expand=Trader)"><code>https://api.uktradeinfo.com/Commodity?$filter=Hs6Code
 eq '010129'&amp;$expand=Exports($filter=MonthId ge 201901 and MonthId 
le 201912 and startswith(Trader/PostCode, 'CB8'); 
$expand=Trader)</code></a></li>
<li>
<p>Make the request.</p>
</li>
</ol>
<p>The API will return a JSON response containing two commodities:</p>
<ul>
<li>one with id <code>1012910</code> and an empty list of exports</li>
<li>one with id <code>1012990</code> and a list of exports</li>
</ul>
<p>Each export’s trader is also expanded, showing you their company name and address. Only exports for traders with a post code beginning with ‘CB8’ have been returned.</p>
<p>To learn more about using the API, refer to <a href="https://www.odata.org/getting-started/basic-tutorial/" title="OData Basic Tutorial">Open Data Protocol(OData) querying tutorials</a>.</p>

            <div id='api-limits'>
                
            <h2 class="govuk-heading-l">API limits</h2>
        <div class="app-rte-content">
            <h3>Response count limit and pagination</h3>
<p>There is a 40,000 item limit in the response. These include:</p>
<ul>
<li>imports, exports, trades, traders</li>
<li>overseas and regional trade statistics</li>
</ul>
<p>Queries to these entities will paginate if more items than the limit allows are returned. This is set to make sure that the API is not overloaded by too many large requests - and that it does not timeout.</p>
<p>When the API paginates the results, this new field <code>@odata.nextLink</code>, will be included in the response. This field includes the URL that can be used to fetch the next page of results. All of the required query parameters are pre-populated.</p>
<p>Or, you can do this by setting the query parameter <code>$skip=40000</code> in the URL (and then 80000, 120000, and so on.). Custom pagination can be achieved for page sizes smaller than the limit. Use a combination of the <code>$skip</code> and <code>$top</code> query parameters for this.</p>
<p>The limit only applies to the final response: aggregations and filtering are still made across the whole dataset before the limit is applied.</p>
<h3>Query rate limit</h3>
<p>Users of the API are rate-limited to 60 requests per minute. If too many requests are made within that timespan, responses will:</p>
<ul>
<li>fail </li>
<li>state that the limit has been reached</li>
</ul>
<p>Upon reaching the limit, a user must wait up to a minute before making any more requests.</p>
