                <h1>Introductory Tutorial <a name="introduction"></a></h1>
<p>Welcome to the introductory USAspending API tutorial. This tutorial is designed for people who aren't familiar with APIs and how to use them. If you already know what an <em>endpoint</em> is and the difference between <code>GET</code> and <code>POST</code>, you'll want to visit <a href="/docs/endpoints">Endpoints</a>. The <a href="https://api.usaspending.gov/docs/">Documentation Index</a> provides links to introductory resources and tutorials to help you get started.</p>
<h2>What's an API? <a name="whats-an-api"></a></h2>
<p><em>API</em> stands for <em>Application Programmer Interface</em>. APIs make it easy for computer programs to request and receive information in a format they can understand.</p>
<p>If you're looking for federal spending data that's designed to be read by humans instead of computers, you should head to <a href="<a href="https://www.usaspending.gov">https://www.usaspending.gov</a>">our website</a>.</p>
<h2>Using the API <a name="using-the-api"></a></h2>
<p>The next few sections will cover different ways to access the API, how to filter the data, how to use autocomplete endpoints, and how to find more information.</p>
<p>You do not need to complete this tutorial in its entirety to get started. Feel free to stop and experiment with your own ideas as you progress.</p>
<h2>Endpoint Overview <a name="endpoint-overview"></a></h2>
<p>When you type a URL into your browser, it usually returns a web page: a document that your browser knows how to display for you to read. APIs use URLs too, but instead of returning formatted web pages, API URLs return data that is structured so computers can easily parse it. API URLs are called <em>endpoints</em>. Just as many pages make up a website, many endpoints make up an API.</p>
<p>The USAspending API supports a number of endpoints. For example <code>/api/v2/search/spending_by_award/</code> is our Advanced Award Search endpoint for the Spending by Award table.</p>
<h4>GET vs POST requests <a name="get-vs-post"></a></h4>
<p>Most endpoints support both GET and POST methods for making a request.</p>
<p>Requests for a specific record (with a known numerical identifier) are made via a GET request. For example, a request to <code>/api/v2/references/agency/456/</code> would retrieve the agency's metadata with identifier <code>456</code>.</p>
<p>You can also use simple filters in a GET request. An example of this would be <code>/api/v2/financial_balances/agencies?funding_agency=775&amp;fiscal_year=2017</code>, which would retrieves financial balance information by funding agency, with the identifier of <code>775</code> and a fiscal year of <code>2017</code>.</p>
<p>POST requests are leveraged in situations where more advanced filtering is required. For example, <code>/api/v2/search/spending_by_award/</code> would have filters as such:</p>
