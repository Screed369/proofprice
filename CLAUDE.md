# ProofPrice (code name: pricepaid) — guide for every Claude session

ProofPrice answers one question for AI agents worldwide: **"what did people actually pay for X, here, recently?"**
It returns a price range (median, 10th–90th percentile, sample size, period, confidence, source, licence) built
from real transactions: official open data now, verified receipts (DKIM-sealed order emails) later.

## Code map (plug-in architecture, v0.3)
- `sources/<id>/` — ONE FOLDER PER DATA SOURCE. `index.ts` = manifest (`defineSource`: category, countries,
  param notes, examples, `handle`, optional `harvest`/`historyKey`); `source.ts` = `INFO` (licence, attribution)
  + exported pure parsers + fetch logic; `source.test.ts` = tests with a fixture copied from the live format.
  `sources/_template/` is the starting point and its README is the recipe.
- `categories/<id>/index.ts` — one per MCP tool / REST path (`fuel` → `pricepaid_fuel_prices_now` + `/api/v1/fuel`,
  `home-sales` → `pricepaid_home_sales` + `/api/v1/home-sales`). Shared parameters; sources add notes/values/extras.
  Never rename a tool once public.
- `lib/registry.ts` — builds everything from the folders: tool schemas, routing, coverage, examples, history.
  `lib/registry.generated.ts` is generated by `scripts/gen-registry.mjs` on install/build/test. Never edit or commit it.
- `app/api/mcp/route.ts` — mounts the MCP server (mcp-handler 2.x, stateless Streamable HTTP). The tool list lives in
  `lib/mcp-tools.ts`: one tool per category + coverage, plus a history tool once the library holds `minDays` days. Every tool has a
  title, the four read-only annotations, an `outputSchema` (`lib/schemas.ts`, permissive) and returns `structuredContent`.
  Service version: `SERVICE_VERSION` in `lib/site/constants.ts` (OpenAPI, MCP serverInfo, server.json all read it).
- `lib/stale.ts` + `runCategory` in `lib/registry.ts` — stale-if-error, once for every source: if a live source times out or
  returns 5xx and the library holds a snapshot of the same source/area/item from the last 7 days (source has `harvest` +
  `historyKey`), the answer is that copy (status ok, `extra.stale` true, snapshot date in `period`/`as_of`, notice says so).
  A smoke test that passes with `extra.stale: true` (or an `X-ProofPrice-Stale` header on REST) means the live source is down.
- `app/api/v1/[category]/route.ts` and `[category]/history/route.ts` — REST for every category. Also `coverage`,
  `library` (library status for the Monitor), `receipts/verify`, `receipts/sender-check`.
- `lib/answer.ts` + `lib/stats.ts` — the one answer format and the statistics. Do not change the answer shape without a Decision.
- `lib/library/` + `library/` — the **price library**: daily aggregate CSVs per source, written by
  `scripts/harvest.ts`, run every day at 03:17 UTC by `.github/workflows/harvest.yml` (GitHub Actions, free),
  committed to `main`, and shipped with each deployment. Aggregates only. To move to a database later, replace
  `lib/library/store.ts` only.
- `lib/openapi.ts` — openapi.json and llms.txt, generated from the registry. `lib/receipts/*` — DKIM receipt verifier.
- `tests/registry.test.ts` — the gate every manifest must pass; its messages say what to fix.

## How to add a source (the Builder recipe)
See `sources/_template/README.md`. In short: facts first (Notion Source Pipeline), copy `_template` to
`sources/<cc>-<topic>`, fill `source.ts` + `index.ts` + `source.test.ts`, add `harvest()` for bulk files or feeds worth
tracking, then `npm ci && npm test && npm run typecheck && npm run build`. You touch only your own folder.
Branch `src/<id>`, push, preview-deploy, test the example live, merge to `main`.

## Commands
- `npm ci` (generates the registry) · `npm test` · `npm run typecheck` · `npm run build` · `npm run harvest -- <id>`
- The workspace shell usually cannot reach government sites; test live behaviour through a Vercel deployment.
  The collector runs on GitHub Actions, which can reach them.
- **Probe** (see a government file's real format from GitHub's servers):
  `gh workflow run probe.yml -R Screed369/proofprice --ref main -f url=<https url> -f name=<short-id>`, wait ~40 s, then
  `git fetch origin +refs/heads/probes:refs/remotes/origin/probes && git show origin/probes:probes/<short-id>.txt`.
  One plain GET, honest user agent; official open-data URLs only.

## Deploying and testing
- Preferred: push to GitHub, then deploy with the Vercel connector `create_deployment` using
  `gitSource {type:"github", org:"Screed369", repo:"proofprice", ref:"<branch>"}` and `project` = the project id above
  (target `production` only from `main` after every check passes).
- Preview deployments are protected by Vercel Authentication: test them with `web_fetch_vercel_url`.
  Production is public at https://proofprice.com.
- Production smoke tests (all must return status "ok"): `/api/v1/coverage`, plus every path in the `examples` list
  that `/api/v1/coverage` returns (the first example of each source). Also check `/api/v1/library` for collector errors.
- The library only reaches production when `main` is deployed: the daily Librarian task deploys `main` after the harvest.
- If production breaks, redeploy the last good deployment and log it in Notion (Run Log + Source Pipeline status "Broken").
